# WiFi 链路优化与诊断

Intel AX200 + 小米路由器（Xiaomi_F651_5G）的实测优化记录。适用场景：视频卡顿、内网传输慢、链路质量排查。

## 一键诊断

```bash
wifi-diag          # 信号/重传率/协商速率/周边 AP，30 秒采样
```

## 已确认的最优配置（客户端侧，全部到位）

| 项目 | 状态 | 说明 |
|---|---|---|
| 信道 | 157（5785MHz） | 实测周边 AP 最少；**36 信道拥挤是抖音卡顿根因** |
| 频宽 | 80MHz | 160MHz 占满信道、收益对宽带无感，不推荐 |
| 网卡省电 | NM `802-11-wireless.powersave=2`（disable） | `iw dev wlp35s0 get power_save` 应为 off |
| 发射功率 | 22dBm（拉满） | `iw dev wlp35s0 info \| grep txpower` |
| 天线 | AX200 双天线竖直、呈 60～90° 扇形 | 并排/耷拉是最差姿态 |

## 踩坑记录（2026-10-12）

- **信道 36 重传率 10.4%**（峰值 40%+）→ TCP 反复 RTO 退避 → 抖音播放"看到一半缓冲"。换 **157** 后重传率降至 1.5～3%，卡顿消失
- 判断链路问题先看重传率：`iw dev wlp35s0 station dump | grep -E "tx retries|tx packets"`，**>5% 即该换信道**
- 信号稳定无衰落（60s 全在 -67～-69dBm）= 距离/遮挡问题，搬位置；信号波动大 = 干扰问题，换信道
- AX200 是 2x2 网卡，信号 -69dBm 只协商单流（NSS=1，360Mbps）；-60dBm 以内才上双流（~1200Mbps）

## 大文件内网传输（唯一值得冲 2x2 的场景）

按性价比排序：

1. **插网线**（台式机网口闲着）：唯一稳定跑满千兆的方案，WiFi 再优化实际也只有 700～800Mbps 且随距离波动
2. 查路由器后台 5G 频段是否被限制单流/兼容模式（192.168.31.1）
3. 调机箱位置/天线角度冲 2x2

**判断标准**：实际互传速率 <600Mbps 才值得折腾，高于此说明双流已协商上。

日常使用（宽带 ~136Mbps）单流 360Mbps 有 2.5 倍余量，1x1 与 2x2 体感零差别，不必优化。

## 排查方法备注

- `iw dev wlp35s0 scan` 普通用户会报 Operation not permitted（接口被 NM 占用），用 `nmcli device wifi list --rescan yes` 替代
- DNS 若被 Clash TUN 接管（dig 任何服务器都返回 198.18.x），系统级换 DNS 无效，要改 mihomo 配置上游

## 卸载

```bash
rm -f ~/.local/bin/wifi-diag    # 删除诊断命令
```

`iperf3` 与 `system` 模块共用（排障工具），**不要单独卸载**；确认无其他用途时再 `sudo dnf remove iperf3`。
